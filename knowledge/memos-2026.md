## Formative Test 1 (12 Aug 2026, 50 marks)
- Manager wants to extend one LAN to offices in two other cities: inappropriate because a LAN covers a limited area (office/building/campus); the offices are in different cities so can't be one LAN; a WAN interconnects LANs across wide areas. Recommend: a LAN in each office for local end devices, and a WAN to interconnect the three office LANs.
- PC reaches local PC but not a remote server (PC-Switch-Router-Router-Server); junior blames the cable: too narrow - communication depends on many layers/protocols; the fault could be addressing, protocol operation, configuration, data link or physical, so troubleshoot systematically. Layer 3 provides IP addressing and moves data through the network (end to end); Layer 2 frames data for the local medium and gives link-local delivery. Layer 2 addresses can't stay the same end to end: they are only for local delivery on one link; at each router hop the frame is de-encapsulated and the packet re-encapsulated in a new frame for the next segment.
- Switch config lost after power loss: changes were only in running-config (RAM, volatile) and never saved; should run copy running-config startup-config (NVRAM). Passwords visible: enable secret, console/VTY passwords with login, service password-encryption, a banner (MOTD) to warn unauthorised users.
- Conference centre WLAN slow with hundreds of users: WLAN is a shared, half-duplex medium so bandwidth per user drops as users increase. WLAN uses CSMA/CA (contention, avoids collisions); Ethernet uses CSMA/CD (in bus/half-duplex Ethernet).
- Two campus buildings far apart, heavy traffic: choose fiber - longer distances than UTP, higher bandwidth, immune to EMI/RFI, suited to backbones/inter-building links. UTP less suitable: shorter distance (100 m), less immune to EMI/RFI, can't handle the distance and traffic. Flexible study area where students move: wireless; limitations: limited/variable coverage, interference, security concerns, reduced bandwidth as users share it.
- Proprietary vs open standards for a university: choose open standards - interoperability between vendors (2), competition and more choice (1), innovation (1), so more flexibility and no dependence on one supplier (1).
- Browser to web server on another network: multiple protocols needed because devices must follow agreed rules and different protocols do different jobs (application, reliable transport, delivery across networks). TCP/IP layers: application (represents data to the user), transport (communication between devices across networks), internet (best path through the network), network access. Data changes form because of encapsulation: data, segment (TCP)/datagram (UDP), packet, frame, bits.
- Encoding 1011101011 in NRZ-L and Differential Manchester (0.5 per bit each, 10 marks). NRZ-L: H L H H H L H L H H. Differential Manchester (line low before the first bit; 1 = change at start, 0 = no change, always a mid-bit change): bit1 H->L, bit2 L->H, bit3 L->H, bit4 L->H, bit5 L->H, bit6 H->L, bit7 H->L, bit8 L->H, bit9 L->H, bit10 L->H.

## Formative Test 2 (7 Sep 2026, 57 marks; modules 7, 8, 9, 11, 12)
- Switch with empty MAC table, PC-A (Fa0/1) sends to PC-B (Fa0/2): the switch learns PC-A's source MAC against Fa0/1 (refreshes the timer if it exists, updates the port if it moved). PC-B's MAC is unknown, so it is an unknown unicast: flooded out all ports except Fa0/1 (Fa0/2 and Fa0/3). Reply from PC-B: the switch learns PC-B on Fa0/2, and since PC-A is known on Fa0/1 it forwards out Fa0/1 only (no flooding). Learning and filtering is efficient because frames go only out the needed port, cutting unnecessary traffic.
- IP characteristics applied: connectionless (no connection or synchronisation before sending; TCP handles connection-oriented needs); best effort (no guaranteed delivery, IP itself will NOT retransmit a lost packet, no acknowledgements); media independent (works over copper, fibre and wireless regardless of frame/medium).
- IPv4 limits and IPv6 fixes: address depletion (32-bit vs 128-bit); NAT/lack of end-to-end connectivity and complexity (IPv6's huge space removes the need for NAT).
- Low latency: cut-through (forwards once the destination MAC is read). Fast-forward can relay frames with errors (no error check; the destination NIC discards them); store-and-forward checks the CRC and discards bad frames. Duplex mismatch (full on one end, half on the other) causes poor performance/collisions.
- Static vs dynamic routing: small non-redundant branch = static (manual, suits simple topologies with few changes). Large enterprise with multiple routers/paths that changes = dynamic (discovers remote networks automatically, keeps routes up to date, picks the best path and finds new ones when the topology changes).
- ARP scenario PC1 192.168.1.10/24 to PC2 192.168.1.20/24: ARP; broadcast request; PC2 replies with its MAC; the MAC is needed to build the Ethernet frame.
- SLAAC vs stateful DHCPv6 (4): stateful DHCPv6 works like DHCPv4, assigns IPv6 addresses plus DNS etc.; the server assigns AND tracks each client's address (central control); RA flags A=0, O=0, M=1. SLAAC: the device configures its own address without a DHCP server, using the prefix from the router's RA; decentralised, less control; RA flags A=1, O=0, M=0.
- Gradual IPv4 to IPv6 with some IPv4-only apps: dual stack (devices run IPv4 and IPv6 at the same time), so IPv4 apps keep working and IPv6 apps use IPv6, with no need to replace IPv4 equipment immediately: a gradual migration.
- IPv6 compression: fe80:0000:0000:00c2:0000:0000:0000:cdef -> omit leading zeros fe80:0:0:c2:0:0:0:cdef -> compressed fe80:0:0:c2::cdef (2 marks each form).
- EUI-64 with MAC 2001:9aff:0db8 (20:01:9a:ff:0d:b8): split and insert fffe -> 2001:9aff:feff:0db8; first byte 20 = 00100000, flip the 7th bit -> 00100010 = 22 -> 2201:9aff:feff:0db8.
- Subnetting 192.168.5.0/24, max 48 hosts: 4 subnets, 62 hosts each, 255.255.255.192 = /26 = 11111111.11111111.11111111.11000000, magic number 64 (256 - 192). Table (1 mark per cell): 192.168.5.0 (.1-.62, bc .63), .64 (.65-.126, bc .127), .128 (.129-.190, bc .191), .192 (.193-.254, bc .255).

## Formative Test 3 (5 Oct 2026, 50 marks; modules 13-17)
- Firewall techniques: packet filtering, application filtering, URL filtering, stateful packet inspection.
- Threats after access is gained: information theft, data loss and manipulation, identity theft, disruption of service.
- Ping: sends an ICMP Echo Request; a reachable host replies with an ICMP Echo Reply. Problems: Destination Unreachable (host/port/network can't be reached); Time Exceeded (TTL or Hop Limit reached 0, the router discards the packet).
- Sliding window 2001-2400 / 2401-2600 (lost) / 2601-2800 (10 marks): B gets packet 1, packet 2 lost, packet 3 held in B's buffer; B sends ACK 2401 (next byte expected); A retransmits 2401-2600; B then sends ACK 2801.
- Why some apps use UDP and others TCP (4): UDP for apps that tolerate some loss but need speed (voice, video): low overhead, no retransmission delay. TCP for apps needing reliable, ordered delivery (web, email, file transfer): acknowledgements, sequencing, retransmission.
- Protocol + port (1 + 1 each): DHCP UDP 67 (server) / 68 (client); DNS UDP 53; HTTP TCP 80; FTP TCP 21; SMTP TCP 25.
- Hamming 110101 with even parity (4 + 8): 4 check bits (2^4 >= 6 + 4 + 1); positions 10..1, data in 10,9,7,6,5,3 = 1,1,0,1,0,1; P1 (3,5,7,9: 1,0,0,1 = two 1s) = 0; P2 (3,6,7,10: 1,1,0,1 = three) = 1; P4 (5,6,7: 0,1,0 = one) = 1; P8 (9,10: 1,1 = two) = 0; transmitted 1100101110.
- DHCP DORA (6): client broadcasts DHCPDISCOVER; server replies DHCPOFFER (IP, mask, DNS, gateway, lease time); client sends DHCPREQUEST for that offer; server confirms with DHCPACK. DHCPNAK means the offer/requested address is no longer valid, so the client restarts with a new DHCPDISCOVER (2).

## Formative Test 3 (22 Sep 2025, modules 12-17)
- IPv6: 2001:0000:0000:00a3:abcd:0000:0000:1234 -> 2001:0:0:a3:abcd:0:0:1234 -> 2001::a3:abcd:0:0:1234 (or 2001:0:0:a3:abcd::1234; when the zero runs are equal, compress the first/leftmost).
- Configure IPv6 on G0/0/0: interface g0/0/0; ipv6 address fe80::2:1 link-local; ipv6 address 2001:db8:acad:2::1/64; no shutdown; exit.
- Getting a GUA automatically: SLAAC or stateful DHCPv6. GUA = globally unique, internet-routable (like a public IPv4 address), static or dynamic. LLA = required on every IPv6 device, used only on the local link.
- Transport layer responsibilities (5): tracking individual conversations, segmenting data and reassembling segments, adding header information, identifying applications (ports), conversation multiplexing.
- TCP window: initial window 10,000 bytes, MSS 1,460. Window size = max bytes the receiver can accept before an acknowledgement (flow control). A sends 1-10,000 and gets ACK 2,921: B has bytes 1-2,920 and expects 2,921; the window slides forward 2,920 bytes; new send window limit = 10,000 + 2,920 = 12,920. The process is called a sliding window.
- DNS: MX for mail, A (IPv4)/AAAA (IPv6) for web; resolution: the local DNS server checks its own records, forwards the query to other DNS servers until resolved, returns the answer and caches it; tool nslookup.
- Attacks: man-in-the-middle = the attacker sits between two parties, intercepts or modifies traffic (e.g. on shared Wi-Fi reads HTTP credentials). Trust exploitation = compromise a less secure system that a secure system trusts, then use that trust to get in (A trusts B; the attacker takes over B and then reaches A). Password attack methods: brute force, Trojan horse, packet sniffer.
- Router config lost to hardware failure: backups (config files and IOS images on a secure server such as FTP) allow quick restore and less downtime. Best practice: back up on a regular schedule (per security policy); store offsite or in the cloud. Windows tool: Backup and Restore.
- Small business with video conferencing + file sharing: device selection (cost; port speed/types, e.g. 1 Gbps for desktops and 10 Gbps for servers; OS features/services such as QoS for video, NAT, DHCP; expandability with modular devices). Expandability: modular devices with slots, or switches with high-speed uplinks. Redundancy: avoids single points of failure and downtime, e.g. backup switches or parallel links.
